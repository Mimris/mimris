# Preserve manually edited relationship paths after Reload

When a user reshapes a relationship link, saves and reloads the model, moving either connected object must preserve the link's user-authored bends. Endpoint segments may adjust to stay connected. Moving both endpoints together should translate the route according to the existing drag behavior.

Persist the existing `__manualPath` intent marker with relationship-view points. Restore it in both relationship-view import paths and propagate it into GoJS link data, so drag handling continues to recognize the saved path after Reload. Appearance inheritance and resets do not change this geometry.

Compatibility: older files without the marker treat saved point arrays with more than two points as manually shaped, matching the existing saved-path materialization policy. Explicit `false` keeps automatic routing behavior; empty or two-point legacy paths do not acquire a manual marker.

Acceptance: reshape a link, save/reload, move a connected object, and reload again. Interior bends survive and the endpoint remains connected. Automatic links retain existing rerouting behavior.

Drop completion must reanchor endpoints using the moved port's current document center, never a saved endpoint as the port reference. Straight links retain two points and stay connected after releasing the mouse. Preserve interior bends in Normal routes; align adjacent bends only for multi-segment orthogonal routes.

Node moves and delayed route refreshes must preserve the live link's routing choice instead of replacing it with a stale relationship-view or typeview default. Orthogonal and AvoidsNodes links remain axis-aligned through repeated moves of either endpoint; Normal links retain their routing choice.

For saved orthogonal paths, endpoint adjustment must move the whole collinear run up to the first bend, including the extra short endpoint stubs generated by GoJS. Apply the same geometry rules during dragging and drop persistence, so moving a stub cannot introduce a diagonal to the next point.

Project orthogonal endpoints along their saved segment axes when choosing the node boundary. A horizontal incoming segment must meet a vertical node edge rather than run tangentially along its top or bottom border after a move. Preserve the corresponding attachment direction in both drag preview and drop persistence.

Generic container drags capture descendant endpoint locations and internal link routes, as Pool/Lane drags do. If both endpoints translate equally, translate the complete route without reanchoring individual ends. Delayed persistence must retain this final translated route rather than restore the pre-drag snapshot.

Apply the same whole-route translation when dragging multiple selected nodes, whether or not their connecting link is selected. Capturing endpoint locations and bends must not depend on selecting a container.

Reload must preserve saved ordinary manual routes as endpoint bindings and bounds settle, just as it preserves self-loop routes. A live drag preview takes precedence over the saved points; explicitly automatic links retain the normal router behavior.

When materializing automatic ordinary links on Reload, discard temporary `edge-left`, `edge-right`, `edge-top` and `edge-bottom` drawing-port references. Choose facing sides as node-move handling already does. Explicit named model ports, manual-path attachments and self-loop ports remain intact.
